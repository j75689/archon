# Archon

A Go CLI that keeps architecture diagrams in sync with a **first-party package import graph**.

It compares Git revisions with `go/parser` (no LLM for the diagram), writes a canonical Mermaid block between HTML comment anchors, and optionally asks an OpenAI-compatible API to turn the graph diff into release-note prose.

This repository dogfoods itself: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) is generated by `archon sync`.

## Requirements

- Go 1.26+
- `git` on `PATH` (no fetch; missing objects fail)

## Install

```bash
go install github.com/j75689/archon/cmd/archon@latest
```

From a clone:

```bash
make install
# or
make build   # writes bin/archon
```

## Annotate the doc

Put a pair of anchors in the Markdown file (default `docs/ARCHITECTURE.md`):

````markdown
<!-- ARCHON:START:data-flow -->
```mermaid
flowchart LR
```
<!-- ARCHON:END:data-flow -->
````

Text **outside** the comments is never modified. `archon sync` replaces only the region in between.

## Commands

Shared flags: `--from` (left revision), `--to` (default `HEAD`), `--doc` (path relative to the repo root), `-v` / `-vv` (progress on stderr; repeat for per-file).

| Command | What it does | Exit 1 when |
|---|---|---|
| `archon check` | Compare the doc to the graph at `--to`. Ignores `--from`. | Doc missing, anchors missing, or Mermaid stale |
| `archon diff` | Print first-party node/edge changes `--from` → `--to`. Default `--from` is the latest reachable tag. | Graph changed |
| `archon sync` | Write canonical Mermaid for `--to`. Creates or appends anchors if needed. | Never (write success is 0 even if the graph drifted) |
| `archon changelog` | Print the same report as `diff`, plus optional LLM prose. Never writes files. | Never on a successful analysis |

Exit **2** is an execution error (not a git repo, missing `git`, unreadable revision, parse failure, I/O).

`--from` is required for `diff` / `changelog` if there is no reachable tag (`pass --from or create a tag`). `sync` still writes the diagram and warns.

## What counts as the graph

- **In:** packages in the same Go module (from root `go.mod`)
- **Out:** stdlib, third-party, `*_test.go`, `vendor/`, `testdata/`, `//go:build ignore`, generated files (`Code generated` … `DO NOT EDIT`)
- Isolated packages (no first-party imports) still appear as nodes
- Imports of packages that have no included `.go` files do not create edges

Private function / body-only edits do not change the graph, do not rewrite the diagram, and do not call the LLM.

## Configuration

First non-empty value wins: **flags → environment → `./archon.yaml` → `~/.config/archon/config.yaml`**.

```yaml
# archon.yaml
doc: docs/ARCHITECTURE.md
anchor: data-flow
model: gpt-4o-mini
base_url: https://api.openai.com/v1
```

| Env | Meaning |
|---|---|
| `ARCHON_DOC` | Architecture Markdown path |
| `ARCHON_MODEL` | Chat model (default `gpt-4o-mini`) |
| `ARCHON_BASE_URL` | OpenAI-compatible base URL |
| `OPENAI_API_KEY` | API key (do not put keys in YAML) |

The LLM is used only when a key is set **or** `base_url` / `ARCHON_BASE_URL` is set explicitly (for Ollama, e.g. `http://localhost:11434/v1`). It receives the graph diff and truncated commit subjects — never source files. Failures print one stderr line and are ignored.
